# 快速开始

从 clone 到能对话，最短 5 分钟。**不需要任何模型 API Key**——默认跑演示模式。

---

## 一、你需要什么

| 依赖 | 要求 | 说明 |
|---|---|---|
| Node.js | **≥ 20.9**（推荐 22 LTS） | `node -v` 检查 |
| pnpm | 9 或 10 | `npm i -g pnpm@10` |
| PostgreSQL | **14+，建议带 pgvector** | 用 Docker 可跳过手动安装 |
| Redis | 可选 | 不装会自动降级为进程内限流/队列 |
| Docker | 可选 | 只有想一条命令起全栈时才需要 |

> 没有 pgvector 也能跑：向量检索会降级为「词法 + 子串」召回。
> 但**装了 pgvector 更好**，语义检索质量差别明显。

---

## 二、方式 A：Docker 全栈（推荐给第一次试用）

```bash
git clone https://gitee.com/XiaoZuiNiZhenHao/hexcore.git
cd hexcore

# 可选但强烈建议：生成一个真实密钥（不设置会退化为内置默认值，仅本机试用可接受）
echo "APP_SECRET=$(openssl rand -hex 32)" > .env

docker compose up -d --build
```

首次构建约 3~6 分钟（要装依赖 + `next build`）。国内网络直连 npm 源时可能更久，见文末「Docker 构建很久卡在下载依赖」。起来后：

1. 打开 <http://localhost:3000>
2. 第一次访问会跳到 `/register`，**注册的第一个账号自动成为管理员**
3. 登录后左侧栏能看到「示例知识库（演示）」，里面已有一份虚构的员工手册
4. 直接问：`年假有几天？`

你应该看到：回答引用了「二、休假制度」这一节，并在末尾列出参考来源。
再问一个文档里没有的：`公司的股票期权行权价是多少？`
正确表现是**明确说没有找到**，而不是编一个数字。

停止：`docker compose down`（加 `-v` 会连数据一起删）。

## 三、方式 B：本地开发（推荐给要改代码的人）

```bash
git clone https://gitee.com/XiaoZuiNiZhenHao/hexcore.git
cd hexcore

cp .env.example .env.local
# 编辑 .env.local：
#   DATABASE_URL  指向你的 PG
#   APP_SECRET    填一个至少 16 字符的随机串
#     node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"

pnpm install
pnpm dev          # http://localhost:3000
```

数据库二选一：

```bash
# 1) 本机已有 PG
createdb ai_agent_platform

# 2) 用 compose 只起依赖（不带应用）
docker compose up -d postgres redis
```

**表不用手工建**：首次请求时 `ensureInit()` 会自动建表、建索引、补字段、注入预置模型。

## 四、演示模式（默认开启）

不配任何 Key 时，系统用一个**本地确定性回答器**顶替大模型：

- 从检索到的资料里抽取最相关的句子作答，不走网络、不计费；
- 回答开头会标注「演示模式」，避免被误认为模型能力；
- 检索不到时明确拒答。

它能证明的：登录 → 建知识库 → 上传文档 → 切片 → 检索 → 带引用作答 → 拒答，整条链路是通的。
它不能证明的：语义理解、多步推理、工具调用。

### 开关

在 `.env.local` 里：

```bash
DEMO_MODE=1     # 强制演示（即使配了真实 Key 也走本地回答器）
DEMO_MODE=0     # 强制关闭
# 不设置       # 自动：库里没有任何"能解出非空 API Key"的对话模型时才启用
```

Docker 方式默认 `DEMO_MODE=1`；本地开发不设置时走自动判定，所以**配了 Key 就不会误用演示模式**。

### 换成真实模型

1. 登录后进「管理后台 → 模型」
2. 选一个预置模型（OpenAI 兼容端点已内置：DeepSeek / 通义千问 / GLM / Kimi / MiniMax / 混元 / 硅基流动等），填 API Key
3. 或者导出到环境变量再重启，启动时会自动带上：
   ```bash
   DASHSCOPE_API_KEY=sk-xxx      # 通义千问
   SILICONFLOW_API_KEY=sk-xxx    # 硅基流动
   ZHIPU_API_KEY=xxx             # 智谱 GLM
   OPENAI_API_KEY=sk-xxx
   MINIMAX_API_KEY=xxx
   ```
4. 把 `DEMO_MODE` 设为 `0` 并重启

> 想用上语义检索，还要在后台配一个 `capabilities` 含 `embedding` 的模型，
> 再回「知识库」点「重新索引」。没配则走词法召回，能用但不如语义准。

## 五、验证安装是否正常

```bash
pnpm typecheck        # 类型检查，应为 0 错误
pnpm test             # 单测，应为全绿（约 1 分钟）
pnpm check            # 上面两项 + 界面规范检查
```

评测基线（需要数据库已初始化，且 `EVAL_RUN=1` 才会跑）：

```bash
EVAL_RUN=1 pnpm eval                     # 用真实模型跑
DEMO_MODE=1 EVAL_RUN=1 pnpm eval         # 完全离线跑，不需要任何 Key
```

评测集会打印逐条明细，并和 `evals/baseline.json` 的基线比较。低于基线时会失败并提示
「先跑 `pnpm eval:diff` 归因，不要直接调低这个数」——这条纪律是有意的：
调低基线等于把退化包装成通过。

## 六、常见问题

**登录后立刻掉线**
内网用 HTTP 部署时，Secure Cookie 不会被回传。在 `.env.local` 加 `COOKIE_SECURE=0` 重启。

**所有页面 500，日志提示 `[auth] 拒绝服务：APP_SECRET 未设置`**
生产模式下弱密钥会**拒绝启动**（防止用公开密钥伪造管理员会话）。
设置一个至少 16 字符的随机 `APP_SECRET`。仅本机临时排障可设 `ALLOW_INSECURE_SECRET=1`。

**提问总是「没有找到」**
按顺序排查：① 知识库是否为空；② 文档状态是否 `indexed`；③ 是否刚上传还没建索引；
④ 问题用词是否与文档差异过大（演示模式只做词面匹配，不做同义扩展）。

**Docker 起来后连不上数据库**
`docker compose` 里的 `DATABASE_URL` 用的是服务名 `postgres`，不是 `localhost`。
如果你改成了自己的外部库，注意容器内的 `localhost` 指容器自己。

**端口 3000 被占用**
`pnpm dev -- -p 3001`；Docker 方式改 `docker-compose.yml` 里的 `ports` 左侧。

**Docker 启动报 `Ports are not available ... 5432` / `6379`**
本机已经跑着 PostgreSQL 或 Redis，把容器要映射的宿主端口占掉了。在 `.env` 里加两行再 `docker compose up -d`：

```bash
POSTGRES_PORT=5433
REDIS_PORT=6380
```

只改「从宿主机访问」的端口，应用容器内部仍走 `postgres:5432`、`redis:6379`，不需要动 `DATABASE_URL`。

**Docker 构建在 `pnpm install` 阶段失败**
先看报错里的 `MODULE_NOT_FOUND` 路径。若指向 `scripts/` 下某个文件，说明它被 `.dockerignore` 或 Dockerfile 的 `COPY` 漏掉了——`package.json` 的 `prepare` 钩子会在 install 后执行 `scripts/setup-git-hooks.mjs`，该文件必须进构建上下文。

**Docker 构建很久卡在下载依赖**
容器内直连 `registry.npmjs.org`，国内网络常见只有几十 KB/s（日志里会有 `Tarball download average speed ... is below 50 KiB/s` 的告警）。把 `Dockerfile` 里那行安装命令换成带源的写法即可：

```dockerfile
RUN pnpm install --frozen-lockfile --registry=https://registry.npmmirror.com
```

注意改的是**装依赖**的源；给 `npm i -g pnpm` 加 `--registry` 只影响 pnpm 自己的安装，对依赖下载无效。

**没有 Redis 会缺功能吗**
不会。限流退回进程内滑动窗口，异步队列退回进程内后台执行。只是多副本部署时
限流不精确、定时任务需要按副本数关闭（见下）。

**多副本部署要注意什么**
① 除主副本外，其余副本设 `SCHEDULER_ENABLED=false`（Redis 锁只防同一次触发重复执行，
防不了 N 个副本各起一套 cron）；② 文件落在本地盘，多副本需要共享卷；
③ 限流/熔断为进程内状态，副本间不共享。

**上传的文件存在哪**
本地 `data/files/`（Docker 下是 `appdata` 卷）。**这个目录不在版本库里**，备份要单独做。
