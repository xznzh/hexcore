# 界面开发规范（UI Spec · v1）

> **这份文件是界面改动的唯一依据。** 以后新增页面、改样式、修视觉问题，都按这里执行，不再各自发挥。
>
> 配套落地物：
> - 检查脚本 `scripts/check-ui-spec.mjs`（`npm run lint:ui`）—— 机器能判的规则由它兜底；
> - 一键自检 `npm run check`（= typecheck + lint:ui + test）；
> - 改版背景与历史决策见 `docs/界面改版记录-v7.md`；
> - 设计 token 与契约类的**真源**是 `app/globals.css` 顶部 `:root` 与末尾「v7 界面统一层」。
>
> 版本：v1（2026-10-27）。修改本规范时同步改 §12 变更记录，并确认脚本仍然通过。

## 0. 三条硬性要求

| 编号 | 要求 | 怎么算做对了 |
| --- | --- | --- |
| R1 | **颜色只能用变量**，禁止在 TSX / CSS 里写十六进制、`rgb()`、`hsl()` 常量 | `npm run lint:ui` 通过 |
| R2 | **Tag 配色只能用规范配色表**，禁止 `magenta / purple / volcano / lime / geekblue / pink / violet` | `npm run lint:ui` 通过 |
| R3 | 改完界面后，**深浅两套主题 + 1100px 以下宽度**都要看过（截图或真机） | §10 清单第 7、8 条 |

> 违规示例（会被 lint 拦下）：
> ```tsx
> <span style={{ color: '#22d3ee' }}>   // ❌ 硬编码
> <Tag color="purple">内置</Tag>        // ❌ 规范外配色
> ```
> 正例：
> ```tsx
> <span style={{ color: 'var(--accent)' }}>   // ✅
> <Tag color="cyan">内置</Tag>                // ✅
> ```
> 确属例外（第三方嵌入、品牌 logo 等）在该行加注释 `// ui-spec-allow-color: 原因`，并在提交说明里写明。

## 1. 分层结构：token → 契约类 → 页面

界面只允许三层，**不允许页面自己造第四层**：

```
① Design Token     app/globals.css :root / [data-theme='light']   颜色·字号·间距·圆角·阴影·动效
② 契约类（复用）    app/globals.css 末尾「v7 界面统一层」           .page / .toolbar / .cell-sub ...
③ 页面              app/**/page.tsx                               只做「组合 + 传参」
```

- 页面里**不写**颜色常量、不写字号数字、不写 magic number 间距（如 `marginTop: 13`）。
- 页面里**允许**写布局相关的 `display/flex/gap/width`，但数值应来自 token 或业务需要（列宽、图表尺寸）。
- 需要新的通用样式时，加在「界面统一层」段落并同步更新本规范 §附录B，**不要散落在页面里**。

## 2. 颜色

### 2.1 可用变量（全部，不许超纲）

| 类别 | 变量 | 用途 |
| --- | --- | --- |
| 主色家族 | `--accent` | 主按钮、链接、选中态、强调数值 |
| | `--accent-hover` / `--accent-soft` / `--accent-border` | 悬浮 / 柔底 / 描边（**都由 JS 按主色现算，别自己调透明度**） |
| | `--accent-rgb` | 需要带透明度时：`rgba(var(--accent-rgb), 0.12)` |
| | `--accent-2` | **渐变第二色只能用这个**（主色同色相深调），禁止再出现第二套色相 |
| 中性 | `--bg` / `--bg-subtle` / `--panel` / `--panel-hover` | 页面底 / 次级底 / 卡片底 / 悬浮 |
| | `--border` / `--border-strong` | 常规描边 / 强调描边 |
| | `--text` / `--text-secondary` / `--muted` | 正文 / 次要 / 弱化 |
| 语义 | `--success` / `--warning` / `--danger` | 成败与风险，**不要用主色表达状态** |
| | `--user-bubble` / `--user-bubble-text` | 用户气泡底与**其上文字色**（主色多为亮青蓝，白字对比度不够） |
| 其他 | `--result-bg` `--hover-bg` `--shadow-*` `--ease` `--dur` `--dur-fast` `--radius-*` `--fs-*` `--sp-*` | 见附录 A |

### 2.2 换肤必须成立

主题色是用户可换的（`ThemeProvider` 注入）。所以：

- 任何与主色相关的视觉，必须用 `--accent` 家族；**不允许出现第二个硬编码色相**（v7 之前就是紫色 `rgba(147,51,234)` 与青色 `rgba(14,165,183)` 散落在背景光晕、logo、气泡里，换色即破功）。
- 渐变必须写成 `linear-gradient(135deg, var(--accent), var(--accent-2))` 这一种形态。
- 判断标准：**换任意主色后截一张图，页面上不应该出现"另一套色系"的色块。**

### 2.3 语义色不与主色混用

| 场景 | 用什么 | 不要用 |
| --- | --- | --- |
| 成功 / 启用 / 健康 | `--success`、`green`、`success` | `--accent` |
| 失败 / 撤销 / 危险 | `--danger`、`red`、`error` | `--accent` |
| 需关注（待审批、额度告警） | `--warning`、`orange`、`warning` | `gold`（gold 另有语义，见下表） |
| 中性 / 未知 | `--muted`、`default` | 灰写死的 `#888` |

### 2.4 Tag 配色表（R2）

| 语义 | 取值 | 典型例子 |
| --- | --- | --- |
| 技术标识 / 分类枚举 | `blue` | HTTP 方法、模型名、项目名、工具名、`后台`、`PPT` |
| 归属与来源 | `cyan` | `内置`、`团队`、第三方能力、待办来源、对话里的关联项 chip |
| 成功 / 启用 | `green` / `success` | `启用`、`健康`、`直接调用` 之外的成功态 |
| 失败 / 撤销 / 危险 | `red` / `error` | `已撤销`、`异常` |
| 需关注 | `orange` / `warning` | `需审批`、`访客` |
| 特殊强调 | `gold` | `★ 默认`、`语义缓存命中` |
| 中性 | `default`（不写 color） | `个人`、`同步`、`停用` |
| 禁止 | `magenta` `purple` `volcano` `lime` `geekblue` `pink` `violet` | —— |

> 枚举型标签（≥3 个值同屏，如技能角色 `supervisor/planner/worker/critic`）只从**允许集合**里取：`blue / cyan / green / orange / gold / default`，且同类同色、跨页面一致。
> 现有映射：`supervisor=cyan`、`planner=blue`、`worker=green`、`critic=orange`。

### 2.5 深浅双向验证

任何新增颜色相关样式，必须在 `data-theme='dark'` 与 `'light'` 下都可见：
- 暗色下不要用「深底 + 深字」，浅色下不要用「白底 + 亮色字」；
- 描边在暗底上容易看不见 → 用 `--border`，需要更明显用 `--border-strong`；
- 拿不准就截图对比，不要凭感觉。

## 3. 布局与密度

### 3.1 页面骨架（照抄）

```tsx
<div className="page">
  <PageHeader
    title="能力目录"
    desc="可选的一句说明"
    extra={<Button type="primary" icon={<PlusOutlined />}>新建</Button>}
  />
  {/* 有 Tab 就加 className="page-tabs" */}
  <Tabs className="page-tabs" items={...} />
</div>
```

- 页面外层固定 `.page`（`max-width: 1200px; margin: 0 auto`），**不要自己再加容器宽度**。
- 标题一律交给 `PageHeader`，禁止页面内自己写 `<Title level={4}>` 当页头。
- 右侧操作区放 `PageHeader` 的 `extra`（内部已 `flex-wrap`）。

### 3.2 间距只用 `--sp-*`

| token | 值 | 用途 |
| --- | --- | --- |
| `--sp-1` | 4px | 图标与文字、紧密元素之间 |
| `--sp-2` | 8px | 标签之间、行内元素 |
| `--sp-3` | 12px | 工具条元素之间、卡片内小块 |
| `--sp-4` | 16px | 区块之间、卡片之间 |
| `--sp-5` | 24px | 大区块分隔 |
| `--sp-6` | 32px | 页面级分隔（少用） |

- 卡片之间统一 `--sp-4`（`.page > .ant-card + .ant-card` 已内置，不要重复加 `marginBottom`）。
- 禁止 `marginBottom: 16` 这类裸数字（除非是 antd 组件的固定属性且无替代）。

### 3.3 工具条（上传 / 筛选 / 按钮行）

**必须**用 `.toolbar`，它保证控件等高（34px）、间距一致、小屏自动换行：

```tsx
<div className="toolbar">
  <Upload {...uploadProps}><Button icon={<UploadOutlined />}>选择文件</Button></Upload>
  <Select placeholder="归属项目（可选）" style={{ width: 220 }} />
  <Button type="primary" loading={uploading}>上传</Button>
  <span className="toolbar-hint">支持 PDF / Word / Markdown，单文件 ≤ 100MB</span>
  <div className="toolbar-end">{/* 右侧次要操作 */}</div>
</div>
```

禁止用 `<Space>` 拼工具条（控件高低不齐，这就是 v7 之前「按钮堆在一起」的观感来源之一）。

### 3.4 卡片与栅格

- 指标卡：`.stat-row` + `.stat-card-item`（四卡等高、数值 22px）。栅格版：`.stat-grid` + `.stat-card`。
- 内容卡列表：`.work-grid`（`auto-fit, minmax(280px, 1fr)`）。
- 卡片 `min-height` 不超过 **132px**；空态用 `.tile-empty` 占位，**不要靠固定高度撑版面**。

## 4. 表格（最容易翻车的地方）

### 4.1 列宽与长文本

- 每个文本列**必须**给 `width`，或至少 `ellipsis: true`；否则内容一长整行被撑开、操作列被挤出视口。
- 长值（URL、路径、文件名）单行省略 + `title` 悬浮看全：

```tsx
<span title={c.path} style={{
  minWidth: 0, overflow: 'hidden', textOverflow: 'ellipsis', whiteSpace: 'nowrap',
}}>{c.path}</span>
```

- 列多时开 `tableLayout="fixed"` + `scroll={{ x: <总宽> }}` 兜底；此时**新增列必须同步调宽度**。

### 4.2 操作列：最多 2 个可见按钮

| 规则 | 说明 |
| --- | --- |
| 主操作留在外面 | 该行最常用的那一个（运行 / 测试 / 调用 / 详情），样式为 `size="small"` 默认按钮 |
| 其余进 `⋯` | `<Dropdown menu={{ items }}><Button size="small" icon={<MoreOutlined />} /></Dropdown>` |
| 顺序 | 主操作在最左，`⋯` 在最右 |
| 危险项 | 菜单里加 `danger: true`，并二次确认 |
| 对齐 | 操作列 `align: 'right'` + 固定 `width` |

> 判据：**1440px 宽度下，操作列不应换行；1100px 下允许折行但不允许出横向滚动条遮挡操作。**

### 4.3 名称 + 描述

用 `.cell-sub`（单行截断 + 弱化色），不要用 `<Paragraph ellipsis>`（内边距和行高不受控）：

```tsx
<Text strong>{c.name}</Text>
{c.description && <div className="cell-sub" title={c.description}>{c.description}</div>}
```

### 4.4 空态

| 场景 | 做法 |
| --- | --- |
| 表格无数据 | `<Empty image={Empty.PRESENTED_IMAGE_SIMPLE} />`（全局已缩小到 44px） |
| 卡片内无数据 | 套 `.tile-empty`（虚线紧凑占位块，内部插画自动隐藏） |
| 无数据 ≠ 无权限 ≠ 加载失败 | 三者必须**文案不同**（见 §5.2） |

空态文案必须给**下一步**，禁止只写「无数据」：

- ✅「还没有会话 · 点左侧「新建对话」开始」
- ❌「暂无数据」

### 4.5 分页

| 场景 | 约定 |
| --- | --- |
| 客户端列表 | 超过 10 条才显示分页：`pagination={list.length > 10 ? { pageSize: 10, showSizeChanger: false, size: 'small' } : false}` |
| 服务端分页 | `total` 必须来自接口，`pageSize` ≤ 50（日志类 50，业务类 10~20） |
| 禁止 | 一次性拉全表再前端切片（数据量一涨就卡） |

### 4.6 危险操作

- 行内删除：`Popconfirm`（文案要说清影响范围，如「撤销后连接器及其全部能力将不可用」）。
- 需要输内容/复杂确认：`App.useApp()` 的 `modal.confirm`。
- **禁止** `Modal.confirm` / `message.xxx` 静态方法 —— 它们读不到主题 token，暗色下是白底弹窗。

## 5. 状态：加载 / 空 / 错 / 无权限

### 5.1 加载态

| 位置 | 用什么 |
| --- | --- |
| 页面级 | `Skeleton` 或居中 `Spin` + 一行说明文字 |
| 区块/表格 | `loading` 属性（表格）或 `<Spin size="small" />` |
| 按钮触发 | 按钮 `loading`（不要既 loading 又弹全局遮罩） |

禁止裸文字「加载中…」。

### 5.2 四态必须区分

| 态 | 文案示例 | 视觉 |
| --- | --- | --- |
| 加载中 | 「正在校验访问权限…」 | Spin |
| 无数据 | 「还没有文件 · 到「文件」页上传」 | Empty / `.tile-empty` |
| 加载失败 | 「加载失败，请稍后重试」+ 重试按钮 | `--danger` 文案 |
| 无权限 | 「🔒 无访问权限」+ 返回入口 | `.notfound-wrap` |

**最常见的错误是「把 403 / 500 渲染成空列表」** —— 用户以为没数据，实际是没权限或服务挂了。

### 5.3 权限闸门（模板，照抄 `app/admin/AdminClient.tsx`）

页面级权限判断必须是三态，**先确认身份再拉数据**：

```tsx
const [gate, setGate] = useState<'checking' | 'ok' | 'denied'>('checking');

useEffect(() => {
  (async () => {
    const r = await fetch('/api/auth/me');
    if (r.status === 401) { window.location.href = '/login'; return; }
    const me = r.ok ? await r.json() : null;
    if (!me || me.role !== 'admin') { setGate('denied'); return; }   // 不触发任何后台数据请求
    setGate('ok');
    await loadAll();
  })();
}, []);

return gate === 'checking' ? <div className="admin-gate"><Spin />正在校验访问权限…</div>
     : gate === 'denied'  ? <NoAccess />
     : <真实内容 />;
```

**禁止**：`noAdmin` 这种「初值 false + 无条件 loadAll」的写法 —— 会先渲染一遍完整界面再被替换（闪屏 + 白打一堆 403 请求）。

### 5.4 接口返回值兜底

列表页取数必须防「错误对象进 dataSource」导致整页崩：

```ts
// 数组接口：失败/非数组一律 []
if (expect === 'array') return Array.isArray(j) ? j : [];
// 对象接口：失败/非对象一律 null
return j && typeof j === 'object' ? j : null;
```

- `401` → 跳 `/login`
- `403` → 落 `denied` 态
- 其他非 2xx → 空数据 + 可重试提示（不要静默）

### 5.5 反馈文案

- 优先用后端返回的 `error` 字段：`message.error(j.error || '操作失败')`。
- 成功提示要带对象名：「已导入技能：会议纪要整理」。
- 长任务先 `message.loading(..., 0)` 再替换结果，避免"转圈但没反馈"。

## 6. 交互

### 6.1 按钮层级

| 层级 | 样式 | 一屏最多 |
| --- | --- | --- |
| 主操作 | `type="primary"` | **1 个**（页面级新建/保存/发送） |
| 次操作 | `default` | 若干 |
| 次要/低频 | `type="text"` 或进 `⋯` | —— |
| 危险 | `danger` | —— |

- 表格行内**不用** `primary`（一屏十几行全是主色按钮 = 没有主次）。
- 一个区块里出现两个 `primary` 时，必须问自己"哪个才是主操作"。

### 6.2 折叠菜单的可发现性

把低频操作放进 `⋯` 是**为拥挤让步**，代价是发现性下降。所以：

- `⋯` 按钮必须有 `Tooltip`（如「更多操作」）；
- 首次进入含关键折叠项（导出、授权）的页面，可加一次性提示；
- 高频操作**永远不许**藏进 `⋯`。

### 6.3 浮层与键盘

- 输入联想浮层：`↑↓` 移动、`Enter/Tab` 选中、`Esc` 关闭，且**点击外部关闭**。
- 任何自定义浮层都要处理 `Esc`，不能只能靠点空白关闭。

### 6.4 破坏性操作文案

必须包含**影响范围**，不能只写「确认删除？」：

- ✅「撤销后连接器及其全部能力将不可用，确认？」
- ✅「彻底删除？连接器及其能力会一并删除，历史调用记录保留」
- ❌「确认删除？」

## 7. 排版与文案

### 7.1 字号只用 `--fs-*`

`11 / 12 / 14 / 16 / 20 / 24`（`--fs-xs … --fs-2xl`）。正文 14，表格正文 14，次要信息 12，辅助标注 11。**禁止 13px、15px 这类中间值**。

### 7.2 数字与时间

- 数量、token、金额：`n.toLocaleString()`。
- 时间：同一列表内保持同一格式（相对时间或 `YYYY-MM-DD HH:mm`），不要混用。
- 百分比：保留 1 位小数（`Math.round(x * 10) / 10`）。

### 7.3 文案

- 按钮用**动词**：`保存` / `运行` / `导出`，不用 `确定`（除确认弹窗外）。
- 空态给下一步（§4.4）。
- placeholder 一行为限，功能说明放 `Tooltip` 或页面 `desc`，不要塞进输入框。

## 8. 可访问性

| 要求 | 做法 |
| --- | --- |
| 图标按钮有名字 | `Tooltip` + `aria-label`（纯图标必须两个都有） |
| 焦点可见 | 不要 `outline: none` 了事；需要自定义时补 `:focus-visible` 样式 |
| 对比度 | 正文对比度 ≥ 4.5:1；主色按钮上的文字用 `--user-bubble-text` 而不是硬编码 `#fff` |
| 键盘可达 | 自定义可点击 `div` 必须可聚焦（优先直接用 `Button`/`a`） |
| 动效可关 | 重要动效考虑 `prefers-reduced-motion`（`globals.css` 已有该分支，新增动画要落进去） |

---

## 9. 性能约束（界面侧）

- 列表接口**服务端分页**，不要「拉全表 + 前端过滤」。
- 首屏不引入重组件（编辑器、图表、富文本）→ 用 `dynamic(() => import(...), { ssr: false, loading })`。
- 不在 render 里发请求；数据加载放 `useEffect`/事件里，且要有并发保护（避免重复请求）。
- 表格 `pageSize` ≤ 20（日志类 ≤ 50）。
- 大列表不要每行都挂 `Tooltip`/`Dropdown`（v7 里连接器页 7 个图标按钮就是双重负担：视觉拥挤 + 每行 N 个浮层实例）。

## 12. 演进规则

### 新增一个设计 token

1. 同时加到 `:root` 与 `[data-theme='light']`（色值必须成对）；
2. 若与主色相关，在 `ThemeProvider` 里按 `cfg.accent` 现算，**不要写死**；
3. 更新本规范 §附录A；
4. 换主题色 + 切浅色主题各截一张图确认。

### 新增一个契约类

1. 加在 `globals.css` 末尾「界面统一层」段落，并注明用途注释；
2. 至少被 2 个页面使用才算"契约类"，否则就地写；
3. 更新本规范 §附录B。

### 修改本规范

1. 改正文 → 改 §变更记录 → 确认 `npm run lint:ui` 仍通过；
2. 若新增了「机器可判定」的规则，同步在 `scripts/check-ui-spec.mjs` 实现，不要只写在文档里。
