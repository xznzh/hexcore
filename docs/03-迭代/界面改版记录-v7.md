# 界面改版记录 · v7（视觉收敛与密度统一）

> 起因：使用中反馈「有的展示色彩不搭」「每章内容拥挤、按钮堆在一起」。
> 方法：**先起本地服务、用 Playwright 登录后逐页截图**再动手改，不靠读代码猜；每轮改完重新截图复核。
> 范围：`app/globals.css`（新增 v7 统一层）、`components/ThemeProvider.tsx`、8 个页面 + 对话组件的局部结构。**不动业务逻辑**（唯一例外是下面 §六 的连接池 bug）。
> 结论：`tsc --noEmit` 0 错误、`vitest` 123 例全过、关键页面真机截图复核（见文末索引）。

---

## 一、三个根因

### 1.1 「色彩不搭」不是配色审美问题，是**颜色有三个来源**

改版前页面同时存在三套颜色来源，换主色后必然打架：

| 来源 | 表现 |
| --- | --- |
| CSS 变量 `--accent`（JS 注入） | 主按钮、链接、图标，随主题变 |
| **硬编码紫色 `rgba(147,51,234)`** | 全局背景第二层光晕（body + 次级背景各一处）、侧栏 logo 渐变、品牌标记渐变 |
| **硬编码青色 `rgba(14,165,183)`** | 用户气泡第二渐变色 |

也就是说：主色换成任意颜色，页面上仍会残留紫 + 青两块不受控的颜色。

**改法**：`ThemeProvider` 注入两个新变量，所有硬编码点改为引用变量。

| 变量 | 含义 | 暗色默认 | 浅色默认 |
| --- | --- | --- | --- |
| `--accent-rgb` | 主色的 RGB 三元组，供 `rgba(var(--accent-rgb), α)` 用 | `34, 211, 238` | `8, 145, 178` |
| `--accent-2` | 主色**同色相**的深调，用于渐变第二色 | `#0091ac` | `#007394` |

`--accent-2` 由 `shade(cfg.accent, dark ? -66 : -30)` 现算，所以换肤时渐变两端始终同色系。

### 1.2 「按钮堆叠」是操作列把全部动作平铺

不是间距问题——是**一列塞了 4~7 个按钮**。技能页 4 个（运行/历史/导出/删除）、连接器页最多 7 个图标按钮、能力目录管理员 4 个、模型配置 4 个。窗口一窄就挤成两行，或者把操作列挤出视口。

**改法**：统一成 **「主操作 + ⋯」**（`Dropdown` 菜单），主操作是这一行最常用的那一个：

| 页面 | 改版前 | 改版后 |
| --- | --- | --- |
| 技能编排 | 运行 / 历史 / 导出 / 删除 | **运行** + ⋯（历史 / 导出 / 删除） |
| 连接器 | 测试 / 健康 / 刷新 / 配置 / 角色 / 撤销 / 删除（7 个） | **测试** + ⋯（健康检查 / 刷新能力 / 编辑配置 / 可见角色 / 撤销 / 删除） |
| 能力目录 | 调用 / 配置 / 授权 / 停用 | **调用** + ⋯（配置 / 授权 / 启用·停用） |
| 管理后台·模型 | 测试 / 设置 Key / 设为默认 / 删除 | **测试** + ⋯（设置 Key / 设为默认 / 删除） |
| 管理后台·用户 | 详情 / 删除 | 保留两个（低频页面，两键可接受），改为**固定列宽** |

顺带把删除确认从静态 `Modal.confirm` 换成 `App.useApp()` 的 `modal` —— 静态方法不读 ThemeProvider 的 token，暗色下弹窗是白底。

### 1.3 「拥挤」是缺一层统一的密度契约

改版前每个页面各自定 padding / 间距 / 表头底色，导致同样视觉重量的东西大小不一。v7 在 `globals.css` 末尾新增一层**统一样式契约**（新增页面直接复用类名即可）：

| 类名 / 选择器 | 作用 |
| --- | --- |
| `.toolbar` | 上传区 / 筛选区 / 按钮行统一横排节奏，内部控件统一 34px 高、`--sp-3`(12px) 间距，小屏自动换行 |
| `.toolbar-end` | 工具条右侧次要操作组 |
| `.cell-sub` | 表格「名称 + 下方描述」的单行截断次级文本 |
| `.stat-row` / `.stat-card-item` | 顶部统计卡四卡等高、数值字号统一 |
| `.tile-empty` | 卡片内空态（虚线紧凑占位块，见 §五） |
| `.admin-gate` | 权限校验中的占位（见 §五） |
| `.ant-table-thead > tr > th` | 表头改小字灰色（原先是一块偏亮色块，比内容还抢眼） |
| `.ant-table-tbody > tr > td` | 单元格 `13px 16px`，末行去掉底线，操作列 `nowrap`、按钮 `flex-shrink:0` |
| `.ant-tag` | 统一 6px 圆角 / 20px 行高 / 500 字重，去掉「胶囊过圆」的噪音 |
| `.page-tabs` | Tab 与内容间距、Tab 下方的表格包一层边框，不再「悬空」 |

另外两处针对性收敛：

- **主按钮光晕减弱**：`box-shadow` 从 `-12px` 收到 `-8px`，暗底上不再发亮刺眼。
- **`Segmented`（全部/个人/团队）**：原来是纯青实心块，和旁边「添加记忆」主按钮抢焦点 → 改成「主色柔底 + 主色文字」（`itemSelectedBg` 用 `--accent-soft`）。

## 五、第二轮补齐的两个遗留项

### 5.1 管理后台会先闪一下后台界面

**根因**：`useEffect` 里**无条件调 `loadAll()`**，而 `noAdmin` 初值是 `false`。所以 `/api/auth/me` 还没回，界面已经按「管理员」渲染了一次完整外壳（空表 + 一排操作按钮），403 回来才被替换成「无权限」——既闪屏，又白打 5 个注定 403 的接口。

**改法**：`noAdmin: boolean` → 三态 `gate: 'checking' | 'ok' | 'denied'`，初值 `checking`。

```
启动 → gate='checking'（渲染 .admin-gate 占位）
     → GET /api/auth/me
        ├─ role !== 'admin' → gate='denied'（直接「无权限」，不调 loadAll）
        └─ role === 'admin' → gate='ok' → loadAll() → 渲染 7 个 Tab
```

`getJson` 里运行期遇到 403 也统一落到 `denied`（缓存过期、角色被降级等）。

### 5.2 工作台空态卡片偏空旷

**根因**：`.work-card { min-height: 168px }` 硬撑高度，里面只放一个空插画。

**改法**：

- `.work-card`：`min-height: 168px` → `132px`，并改为 `display:flex; flex-direction:column`。
- `.tile-empty`：从「8px 内边距 + 插画」改成 `flex:1` 的**虚线紧凑占位块**（`min-height:76px`、`--bg-subtle` 底、hover 提亮边框），并 `display:none` 隐藏内部插画——这个位置插画只会放大「空」的感觉。
- 空态文案补引导（不再是干巴巴的「无待办」）：
  - 待办 → 「暂无待办 · 在对话里说「记一下：…」即可生成」（已核对后端确有 `create_todo` 工具，`app/api/chat/route.ts:652`）
  - 会话 → 「还没有会话 · 点左侧「新建对话」开始」
  - 文件 → 「还没有文件 · 到「文件」页上传，或在对话里直接发」
  - 定时任务 → 「暂无定时任务 · 到「定时任务」页创建」
  - 产物 → 「还没有产物 · 在对话里让 AI 生成文档或 PPT」

## 六、顺手修的一个非界面 bug（不修会表现为「页面空白」）

`lib/db.ts` 的连接池原来是 `const client = postgres(DATABASE_URL, { max: 5 })`，**没有做 `globalThis` 单例**。`next dev` 每次热更新都会重新执行模块、新建一个池，改几十次就耗尽 PostgreSQL 的 `max_connections`，于是接口全 500 —— 从界面上看就是「所有页面都没数据、每页一个大空态」。

截图巡检时反复撞到 `53300 too many clients` 才定位到。现在非生产环境复用同一实例：

```ts
const globalForDb = globalThis as unknown as { __pgClient?: ReturnType<typeof postgres> };
```

（生产环境 `next start` 只执行一次模块，无需挂载。）

## 七、复用到新页面的约定

新建列表页 / 卡片页时，直接套这几条就能保持一致的观感：

1. 页面外层 `<div className="page">` + `<PageHeader title="..." extra={...} />`。
2. 有 Tab 就 `<Tabs className="page-tabs">`，表格放进 Tab 会自动获得边框与间距。
3. 上传行 / 筛选行一律 `<div className="toolbar">`，右侧次要操作放 `.toolbar-end`。
4. 表格列：文字列给固定 `width`；「名称 + 描述」用 `.cell-sub` 做单行截断；操作列 ≤ 2 个按钮，多的进 `Dropdown`（主操作留外面）。
5. 顶部指标用 `.stat-row` + `.stat-card-item`（`Card size="small"` + `Statistic`）。
6. 空态优先用 `<Empty image={Empty.PRESENTED_IMAGE_SIMPLE} />`；卡片内空态套 `.tile-empty`。
7. 颜色只用变量：`--accent` / `--accent-hover` / `--accent-soft` / `--accent-border` / `--accent-rgb` / `--accent-2`，**不要再写死十六进制或 rgba 常量**。

## 十、v7.1 补充：模型选择器（2026-10-27 下午）

用户反馈：「模型下拉里为什么会有 embedding？」——不是显示问题，是**接口把不该出现的模型也返回了**。

### 10.1 根因

`GET /api/models` 只做了 `visibleRoles` 过滤：

| 漏掉的过滤 | 后果 |
| --- | --- |
| 没有 `enabled` 判断 | 停用的模型也能被选中；服务端 `resolveModel` 返回 null 后**静默降级到默认模型**，用户以为换模型成功了 |
| 没有「对话能力」判断 | `capabilities: ["embedding"]` 的 6 个向量模型进了对话下拉（它们 `visibleRoles` 是 `["admin"]`，所以管理员才看得到，普通成员看不到——这个差异让问题更迷惑） |

真实数据核对：`models` 表 16 条 → 其中 6 条是纯 embedding（embo-01 / nomic-embed-text / text-embedding-3-small / embedding-3 / text-embedding-v4 / BAAI-bge-m3），对话实际可选应为 10 条。

### 10.2 改动

- `lib/ai/providers.ts`：导出既有的 `canChat()`（原先只是模块内私有；`resolveDefaultModel` 一直在用，接口却没用，属于典型的「规则写在一处、用在一处」）。
- `app/api/models/route.ts`：过滤 `enabled` + `canChat` + `visibleRoles`；返回体补 `caps` 与 `contextLength`；排序改「默认模型置顶 + 厂商名 + 模型名」，不随建表顺序抖动。
- `components/chat/types.ts`：`ModelOption` 加可选 `caps` / `contextLength`（`/api/docs`、`/api/ppt` 复用同类型，自动受益）。
- `components/chat/Composer.tsx`：
  - 下拉按**厂商分组**（`openai` → OpenAI、`zhipu` → 智谱 GLM 等 12 个名称映射，未知厂商原样显示），含默认模型的厂商排最前；
  - 每行右侧显示能力与上下文：`默认`（主色描边）/ `工具` / `视觉` / `128K`；
  - 支持按**模型名 / 厂商 / id** 搜索（`optionFilterProp="search"`，另带 `title` 悬浮全量信息）；
  - 空态区分「没有匹配」与「没有可用对话模型（并说明向量/重排模型不会出现在这里）」；
  - 记住上次选择：`localStorage['chat.modelId']`，失效则回落默认模型（此前每次进页面都被重置为默认）。
- `app/globals.css`：新增 `.model-opt / .model-badge / .model-ctx / .model-empty`，全部走 token，无硬编码颜色。

### 10.3 分组下拉的两个实现细节（踩过才知道）

1. `optionRender` **不会**作用于分组头：`rc-select` 在 `OptionList` 里把 `data.group` 走单独分支，分组头用 `label` 直出。所以分组头的展示名就是 `{ label }`。
2. 自定义 `filterOption` 会**先对整个分组对象调用一次**（`useFilterOptions` 里 `matchGroup`），一旦分组返回 true，子项就不会再被过滤。所以这里没用自定义函数，而是用 `optionFilterProp="search"`：分组对象没有 `search` 字段 → 天然判负 → 逐个过滤子项，分组自动只保留命中的子项。

### 10.4 验证

| 项 | 结果 |
| --- | --- |
| 真实数据模拟（只读查库，按新规则过滤） | 16 → 10，6 个 embedding 全部排除 |
| `tsc --noEmit` / `lint:ui` | 0 错误 / 0 违规 |
| 未做 | 真机截图复核（本机 3000 端口是用户正在跑的实例，未干扰；改动靠 HMR 生效，刷新即可看到） |

## 11 · v7.1 走查修复（2026-10-27，用户手册走查暴露）

本轮为了写《用户使用手册-培训版》，用访客账号逐页实操，暴露两个**「文案与实况不一致」**的问题。

### 11.1 禁用的主按钮看起来仍可点

**现象**：访客在「定时任务」页看到「新建任务」是亮蓝色（和可点状态一样），只有鼠标移上去才发现是 `not-allowed`；「文档/PPT」页的「访客为只读角色，无法生成」同样如此。

**根因**：`app/globals.css` 里主按钮渐变用了 `!important`，选择器没排除 `:disabled`：

```css
/* 改前：禁用态也被这条规则命中，渐变背景覆盖掉 antd 的灰化 */
.ant-btn-primary:not(.ant-btn-dangerous) {
  background: linear-gradient(135deg, var(--accent), var(--accent-hover)) !important;
```

**修复**：选择器加 `:not(:disabled)`，并补一条禁用态规则：

```css
.ant-btn-primary:not(.ant-btn-dangerous):not(:disabled) { /* 原渐变光晕 */ }

/* 主按钮禁用态：去掉渐变与光晕，退回统一灰化，让「不能点」一眼可辨 */
.ant-btn-primary:disabled,
.ant-btn-primary.ant-btn-disabled {
  background: var(--border) !important;
  color: var(--muted) !important;
  border: none !important;
  box-shadow: none !important;
  font-weight: 500;
  cursor: not-allowed;
}
```

**影响面**：全站所有禁用态主按钮（不只访客页面）。这也是《界面开发规范》里「禁用态必须一眼可辨」的具体落实。

### 11.2 技能页对访客承诺了做不到的事

**现象**：访客进「技能编排」，页面右上写「可查看与运行既有技能」，行内「运行」按钮也是可点的；点进去抽屉里的「运行」却是禁用的，且 `/api/skills/run` 对访客返回 403「访客无写入权限」。

**根因**：三处口径不一致 —— 页面文案、行内按钮、服务端策略。服务端是对的（运行技能会写运行记录、耗额度），前端两处没跟上。

**修复**：

| 位置 | 改前 | 改后 |
