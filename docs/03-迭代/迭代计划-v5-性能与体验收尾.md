## 二、消息加载卡顿诊断（2026-10-26，已定位四个根因）

1. **DB**：`messages` 表无 `conversation_id` 索引 → 每次加载全表扫描 + 排序（越用越卡）。
2. **接口**：`GET /api/conversations/[id]` 全量返回整段历史（含 sources/trace JSON），长会话数 MB。
3. **链路**：进入 `/chat` 首屏五请求打头，消息请求挂在 conversations 之后串行；流结束还把整段历史再全量拉一遍（双倍加载）；切换会话不清空旧消息 + 无请求取消 → 旧内容串场、竞态覆盖。
4. **渲染**：全量消息一次性同步渲染（每条跑一遍 ReactMarkdown + 8 个 antd 组件），无 memo；流式期间**每个网络分片**触发全列表重渲染。
