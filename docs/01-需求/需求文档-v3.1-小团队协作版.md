# AI Agent Platform —— 小团队协作 AI 智能体平台 需求文档（PRD v3.1 · 小团队协作版）

> 版本：v3.1（基于 v2.0 重构、修正 v3.0 误判）｜ 日期：2026-10-13 ｜ 状态：待评审
> 定位：个人发起、**小团队（约 2–20 人）共同使用**的本地优先 AI 智能体协作平台
> 技术基调：全 TypeScript、本地优先（local-first）、覆盖约 80% 主流 AI 技术
> 对标：豆包（对话体验）+ WorkBuddy（智能体/技能形态）+ 本人 `springai-env-rag` / `local-file-agent`（设计模式平移到 TS）

---

## 0. 本次变更说明（v2.0 → v3.0 → v3.1）

v2.0 是「企业级平台」定位，含 RBAC 四角色、部门树、多租户 SaaS、SSO、合规留存等治理层。
v3.0 我误判为「纯个人单机」，把用户/注册/额度/模型配置全砍了——**这是错的**。
v3.1 修正定位为「小团队协作版」：**保留团队运营必需的治理能力，但全部做轻量化，不做企业级复杂度。**

| v2.0 项 | v3.1 处理 | 理由 |
|---------|-----------|------|
| 用户注册 / 登录 | **保留**（账号密码 + JWT；注册方式可配：开放 / 邀请码 / 仅管理员添加） | 团队必须有多账号 |
| RBAC 四角色 + 部门树 + 数据范围 | **精简为 2–3 角色（Admin / Member / 可选 Guest），砍掉部门树** | 小团队不需要组织架构，两级权限足够 |
| Token 配额 / 计费倍率 / 用量看板 | **保留（团队必需）**，倍率简化为可选 | 团队要控成本、防某人刷爆 API |
| 审计日志 + 合规留存策略 | **保留基础操作日志（谁/何时/做了什么）**，去掉强制留存与合规条款 | 团队需要可追溯，但不需要合规审计 |
| SSO / LDAP / OAuth + 多租户 | **移除**（预留单租户扩展位） | 小团队用账号密码即可 |
| MinIO 对象存储 | **默认本地文件系统，可选 MinIO / S3** | 省常驻服务，团队大再上对象存储 |
| Redis（队列/限流） | **团队推荐引入**（配额原子扣减、限流）；小团队可先用 DB 原子操作兜底 | 多用户并发才需要，单人不需要 |
| Postgres + pgvector | **团队推荐 Postgres**；极小团队可用 SQLite + LanceDB（零运维） | 并发写入与多用户隔离需要真正的 DB |
| NestJS（IoC/Guard/Module） | **回归 NestJS + React 分离**（用户 v2 已确认全 TS + NestJS）；Next.js 仍可作轻量备选 | 治理层恢复后，NestJS 的 Guard/RBAC 样板投资值得 |
| 对话 / RAG / 多 Agent / MCP / 产物 / 记忆 / 可观测 | **全部保留并强化** | 这是「80% AI 技术」的核心载体 |

> 一句话：**治理层按「小团队」做减法，能力层按「80% AI 技术」做加法。**

## 1. 项目概述

### 1.1 一句话定位
**个人发起、小团队共同使用的本地优先 AI 智能体协作平台**：成员像用豆包一样对话，但能调用团队共享知识库、生成文档/PPT、编排多 Agent 工作流、接入工具（MCP），管理员能管用户、分配 Token 额度、配置可用的 AI 模型。默认数据留在本地，可选接入云端模型增强能力。

### 1.2 目标用户（小团队视角）
| 角色 | 说明 |
|------|------|
| Admin 团队管理员（你本人） | 配模型、管用户、分配额度、看用量、查操作日志 |
| Member 普通成员 | 日常对话、用/建知识库、生成文档/PPT、编排技能、用连接器、建定时任务、建项目 |
| Guest 访客（可选） | 只读对话 / 只读知识库，无写入 |

### 1.3 成功标准
- 新成员 5 分钟内：注册/被添加 → 登录 → 选模型对话 → 命中团队知识库 → 拿到带引用的回答。
- 管理员在一个后台页完成「添加用户 + 分配额度 + 配置模型 + 看用量」。
- 对话可无缝升级为「技能 / 多 Agent 任务」，过程可观测、可回放。
- 任何成员超额度时系统按策略拦截/降级/告警，不拖累团队账单。

## 3. 用户与权限（RBAC · 小团队精简版）

### 3.1 角色定义（2–3 个，非四角色）
| 角色 | 说明 |
|------|------|
| Admin 管理员 | 全局：模型、用户、额度、用量、操作日志、系统设置 |
| Member 成员 | 对话、知识库（可配）、文档/PPT、技能、连接器（用）、定时任务、项目 |
| Guest 访客（可选，默认关闭） | 只读对话 / 只读知识库 |

### 3.2 权限矩阵（精简）
| 能力 | Admin | Member | Guest |
|------|:---:|:---:|:---:|
| 对话 | ✅ | ✅ | 只读 |
| 使用知识库 | ✅ | ✅ | 只读 |
| 创建/上传知识库 | ✅ | ✅（团队/个人） | ❌ |
| 生成文档/PPT | ✅ | ✅ | ❌ |
| 技能编排 | ✅ | ✅ | ❌ |
| 定时任务 | ✅ | ✅ | ❌ |
| 连接器配置 | ✅ | 仅使用 | ❌ |
| 用户管理 | ✅ | ❌ | ❌ |
| 模型配置 | ✅ | ❌ | ❌ |
| 额度分配 / 用量看板 | ✅ | 仅自己用量 | ❌ |
| 操作日志 | ✅ | ❌ | ❌ |

> 采用「角色 + 数据可见范围（个人/团队）」双维模型，不做部门树。**知识库/文件/项目支持「个人私有 / 团队共享」两级。**

### 3.3 关键需求
- FR-3.1 注册 / 登录（账号密码 + JWT）。注册方式可配：① 管理员添加；② 邀请码；③ 开放注册（团队内部网建议①或②）。
- FR-3.2 用户管理：Admin 可添加、禁用、改角色、重置密码。
- FR-3.3 角色固定为 Admin / Member（Guest 可开关），权限点不开放自定义（避免过度设计）。
- FR-3.4 数据可见范围：知识库 / 文件 / 项目支持「个人私有 / 团队共享」。
- FR-3.5 基础操作日志：登录、配置变更、额度调整、知识库重建等留痕（不做合规留存策略）。

## 4. 功能需求

### 4.1 对话工作区（核心，对标豆包）
- FR-4.1.1 多轮对话，流式输出（打字机），首字延迟 < 2s（本地小模型可放宽并标注预期）。
- FR-4.1.2 Markdown 渲染、代码高亮、表格、图片、文件卡片。
- FR-4.1.3 支持 `/` 调用技能、`@` 引用知识库 / 文件。
- FR-4.1.4 附件上传（多模态：图片/文档），Shift+Enter 换行、Enter 发送。
- FR-4.1.5 会话管理：新建/重命名/置顶/归档/删除，历史搜索。
- FR-4.1.6 模型选择器：成员在「Admin 配置的可见模型」范围内切换。
- FR-4.1.7 回答可「一键转文档/PPT」「一键升级为技能任务」。
- FR-4.1.8 显示引用来源（RAG 归因），点击跳原文。
- FR-4.1.9 用户对回答点赞/点踩/反馈（用于调优）。
- FR-4.1.10（可选）语音输入/播报（类豆包）；本地模型优先开关。

### 4.2 知识库（RAG，团队/个人两级）
- FR-4.2.1 创建知识库（名称、描述、可见范围【个人/团队】、embedding 模型）。
- FR-4.2.2 文档上传（pdf/docx/md/txt/xlsx/html），批量导入。
- FR-4.2.3 解析流水线：文本抽取 → 清洗 → 切片（256~1024 token、重叠 10~20%）→ 向量化 → 入库。
- FR-4.2.4 检索：向量召回 + 重排（rerank），相似度阈值、TopK 可配。
- FR-4.2.5 引用归因：回答标注来源文档与片段。
- FR-4.2.6 文档增量更新 / 重建索引 / 删除。
- FR-4.2.7 知识库级权限（个人私有 / 团队共享，谁能用、谁能管）。
- FR-4.2.8 解析状态可视化（排队/解析中/失败重试）。

### 4.3 文档 / PPT 生成
- FR-4.3.1 基于对话内容或指定模板生成 Word 文档（`docx` / LibreOffice 转换）。
- FR-4.3.2 基于大纲/内容生成 PPT（多套模板，`pptxgenjs`）。
- FR-4.3.3 产物可编辑、可导出（docx/pptx/pdf）、可归档到项目。
- FR-4.3.4 支持引用知识库素材自动成文。

### 4.4 文件管理
- FR-4.4.1 个人文件区 + 项目文件区。
- FR-4.4.2 上传/下载/预览/重命名/移动/删除。
- FR-4.4.3 文件可「加入知识库」或「作为对话上下文」。
- FR-4.4.4 存储配额（按用户，Admin 可设上限）。

### 4.5 定时任务
- FR-4.5.1 创建定时任务：Cron 表达式 / 周期选择。
- FR-4.5.2 任务内容 = 一段 prompt 或一个已编排技能。
- FR-4.5.3 执行结果可推送（站内信 / 可选邮件 / Webhook）。
- FR-4.5.4 执行历史与失败重试。
- FR-4.5.5 任务归属：个人任务 / 团队共享任务。

### 4.6 连接器（MCP）
- FR-4.6.1 接入外部系统（MCP Server / HTTP API / 数据库）。
- FR-4.6.2 连接器配置（鉴权、端点、参数），连接测试。
- FR-4.6.3 连接器可作为工具被对话/技能调用。
- FR-4.6.4 权限：仅 Admin 可配置；Member 仅可使用已启用连接器。
- FR-4.6.5 内置工具：Playwright 浏览器自动化、代码沙箱（dockerode）、本地文件读写。

### 4.7 技能编排（多 Agent 工作流）
- FR-4.7.1 可视化/声明式编排：节点（LLM / 工具 / 条件分支 / 循环 / 人工确认）。
- FR-4.7.2 多 Agent 角色（Planner 规划 / Worker 执行 / Critic 校验），底层复用引擎。
- FR-4.7.3 技能可版本化、可复用、可分享导出、可标记「个人/团队」。
- FR-4.7.4 技能可被对话 `/` 调用、被定时任务调用。
- FR-4.7.5 运行轨迹可视化 + 回放。

### 4.8 项目管理
- FR-4.8.1 项目 = 会话 + 文件 + 知识库 + 产物的聚合容器。
- FR-4.8.2 项目成员与权限（个人 / 指定成员 / 团队）。
- FR-4.8.3 项目内数据隔离。

### 4.9 用户管理（Admin 后台）
- FR-4.9.1 用户列表：账号、角色、状态（启用/禁用）、额度用量。
- FR-4.9.2 添加用户（创建账号或生成邀请码）、重置密码、改角色、禁用。
- FR-4.9.3 注册方式开关（管理员添加 / 邀请码 / 开放注册）。

### 4.10 模型配置（Admin 后台 · 团队核心）
- FR-4.10.1 多供应商：OpenAI 兼容 / 本地 Ollama / vLLM / DeepSeek / 通义 等。
- FR-4.10.2 模型注册：名称、endpoint、Key（**加密存储**）、上下文长度、能力标签（工具调用/视觉/embedding/rerank）。
- FR-4.10.3 场景路由：默认对话模型 / embedding 模型 / rerank 模型。
- FR-4.10.4 一键连通性测试；启停某模型。
- FR-4.10.5 模型可见范围（哪些角色可用）——**决定成员下拉框里能看到哪些模型**。

### 4.11 额度与用量（Admin 后台 · 团队必需）
- FR-4.11.1 额度分配：按用户 / 角色设置月 Token 额度。
- FR-4.11.2（可选）模型计费倍率：不同模型消耗倍率不同（按输入/输出分别计价）。
- FR-4.11.3 实时用量统计：个人 / 团队看板（趋势图）。
- FR-4.11.4 超限策略：拦截 / 降级到低价模型 / 仅告警（可配置）。
- FR-4.11.5 额度告警（阈值提醒）、额度变更记录。
- FR-4.11.6（可选）用量明细导出。

### 4.12 操作日志（Admin 后台 · 轻量）
- FR-4.12.1 记录：登录、对话（可选记元数据不记全文）、配置变更、额度调整、知识库重建、用户增删。
- FR-4.12.2 列表可查、可按用户/时间筛选。不做强制留存策略。

### 4.13 记忆系统（团队/个人核心）
- FR-4.13.1 短期记忆：会话上下文 + 超长时压缩/摘要。
- FR-4.13.2 长期记忆：向量记忆（语义检索）+ 事实记忆（结构化）。
- FR-4.13.3 记忆作用域：个人记忆 / 可选团队共享记忆。
- FR-4.13.4 设置里可查看 / 编辑 / 清理记忆。

### 4.14 可观测与评估（轻量化）
- FR-4.14.1 运行轨迹：每次对话/技能的执行链路（Langfuse 自托管，或简易本地日志）。
- FR-4.14.2 成本记录：Token 总量与花费趋势，驱动额度系统。
- FR-4.14.3 LLM-as-judge 评估（可选，调 prompt / 技能质量）。

## 5. 底层：多 Agent 引擎（TypeScript 实现）

平台「技能编排」与「复杂对话」背后的引擎：
- **Supervisor** 调度 + **Planner** 规划 + **Worker**（多角色）执行 + **Critic** 校验。
- 统一 **Tool Registry**（含 MCP 连接器）。
- **记忆**：会话上下文 + 长期向量记忆 + 任务工作记忆（按用户/团队作用域隔离）。
- **可观测**：事件流 → SSE / WebSocket 推前端。
- 引擎可选独立运行时（server 经 HTTP 调用），初版可内嵌于后端。
- 安全：工具白名单、权限最小化、敏感操作（删除/发送/外发）二次确认（human-in-the-loop）；Member 仅能调用 Admin 已启用且自己可见的模型/连接器/技能。

## 6. 非功能需求（小团队版调整）

| # | 需求 |
|---|------|
| NFR-1 隐私 | 本地模式数据不出机；云端 Key 加密存储，不落明文 |
| NFR-2 多用户并发 | 支持 2–20 人同时在线；写入用事务/原子操作保证一致 |
| NFR-3 性能 | 首字延迟 < 2s；单步工具 ≤ 30s 熔断；并发请求限流 |
| NFR-4 可扩展 | 新增模型/工具/技能仅注册即可，不改核心；预留单租户扩展 |
| NFR-5 可部署 | 单机 `pnpm dev` 即可跑；推荐 `docker compose` 一键（含 Postgres/Redis/Langfuse） |
| NFR-6 可演进 | 未来若要做部门/多租户，仅需扩展 Role/数据范围，不重构核心 |

## 7. 技术栈建议（全 TypeScript · 小团队版）

> **架构决策（2026-10-13 修正）**：v3.0 因误判纯个人而建议 Next.js 单体；v3.1 恢复团队治理层后，**回归用户在 v2 已确认的「NestJS + React 全 TS 分离架构」**——NestJS 的 Module/Guard/Interceptor 天然适配 RBAC、配额、模型配置等治理面，样板投资对团队是划算的。Next.js 全栈单体仍可作为「极小团队（≤3 人）」的轻量备选，见开放问题 Q1。

| 层 | 技术 | 说明 |
|----|------|------|
| 前端 | **React + TypeScript（Vite）** | 左侧布局 + 对话工作区 + 管理后台 + 实时轨迹 |
| 后端框架 | **NestJS（Node.js + TS）** | 模块化、IoC、Guard/Interceptor，适配 RBAC 与多模块 |
| 实时通信 | **Socket.IO / ws** | 流式输出 + Agent 轨迹推送 |
| AI 编排 | **LangChain.js + LangGraph.js**（或自研 TS 编排器） | 多 Agent 状态机、Tool 调用、Memory |
| 模型接入 | OpenAI 兼容 SDK（TS） | 本地 Ollama/vLLM 与云端统一接口（同 `@ai-sdk/openai` 指向 `/v1`） |
| 认证鉴权 | **Passport + JWT**（NestJS Guard） | RBAC + 可扩展 SSO |
| 数据库 | **PostgreSQL**（团队推荐）/ SQLite（极小团队） | 用户/权限/配额/会话/日志/审计 |
| ORM / 类型层 | **Prisma 或 Drizzle**（TS） | 端到端类型、迁移、省手写 SQL |
| 向量库 | **pgvector**（同库，省运维）/ LanceDB（SQLite 方案时） | 知识库检索 |
| 缓存/队列 | **Redis**（ioredis，团队推荐） | 配额原子扣减、限流、任务队列；小团队可暂缓 |
| 文件存储 | 本地文件系统（默认）/ **MinIO**（S3 兼容，TS SDK，可选） | 文件与产物，团队大再上对象存储 |
| 浏览器工具 | **Playwright（TS 原生）** | 取代 Python browser-use，无需 sidecar |
| 代码沙箱 | **Docker（dockerode，TS）** | 隔离执行代码/命令 |
| 可观测 | **Langfuse**（docker 自托管，可选） | trace + eval |
| Monorepo | **pnpm + Turborepo / Nx** | 前端 + 后端 + 共享类型包统一构建 |

### 7.1 推荐工程结构（Monorepo，端到端类型共享）
```
packages/
  shared/   # 前后端共享：DTO、领域模型、事件协议、权限常量、额度/模型契约
  server/   # NestJS 后端（REST + WebSocket + Agent 引擎 + RAG + 治理面）
  web/      # React + TS 前端（对话工作区 + 管理后台 + 各模块页面）
  agent/    # （可选）独立 Agent 编排运行时，server 经 HTTP/gRPC 调用
```
- `shared` 定义对话消息、工具调用、配额、模型配置、权限等类型，前后端 import 同一份，避免接口漂移。
- 关键收益：模型配置、Token 用量、权限等数据契约变更时，编译期即报错，而非运行时 500。

> 默认**无需 Python sidecar**：Playwright 原生支持浏览器自动化，LangChain.js 覆盖工具生态。仅在接入极个别 Python-only 模型/工具时才考虑轻量 sidecar。

## 9. 数据模型（核心实体，含治理层）

- **User**：id, name, email, password_hash, role(enum), status, created_by, storage_quota
- **Model**：id, provider, name, endpoint, key_encrypted, capabilities[], price_in, price_out, visible_roles[], is_default
- **Quota / Usage**：user_id, period, limit_tokens, used_tokens, model_ratios（可选）
- **Conversation / Message**：会话与消息（含引用、token 消耗、model_id、user_id）
- **KnowledgeBase / Document / Chunk**：知识库（含 scope 个人/团队）、文档、切片（含 embedding、source 元数据）
- **Skill / SkillRun**：技能定义（含 scope）与运行实例（含轨迹）
- **Schedule**：定时任务（cron, target, notify, owner_id, scope）
- **Connector**：外部系统 / MCP 配置（含 enabled、visible 标记）
- **Project**：聚合容器 + 成员 + 权限
- **Memory**：短期 / 长期向量 / 事实（按 user_id / team 作用域）
- **AuditLog / OperationLog**：操作留痕（user_id, action, target, ts）
- **File**：文件元数据（owner, scope, size）

## 11. 已拍板决策（2026-10-13，启动 Demo）

> 原则：**Demo 先把"团队治理 + 对话 + 知识库"跑起来看效果，生产按 v3.1 目标架构演进，优化后置。**

| # | 问题 | 拍板结论 | 说明 |
|---|------|----------|------|
| Q1 | 架构 | **Demo：Next.js 全栈单体 + TypeScript**；生产按 v3.1 演进到 **NestJS + React 分离** | Demo 零外部服务、`pnpm dev` 即跑；生产再补治理层样板 |
| Q2 | 注册方式 | **开放注册**；首个注册用户自动成为 Admin，其余为 Member | Demo 便捷；生产建议改邀请码 |
| Q3 | RBAC 粒度 | **固定 Admin / Member 两角色**（无 Guest、无自定义权限点） | 避免过度设计 |
| Q4 | 数据库 | **Demo：SQLite（单文件）**；生产 **Postgres + pgvector** | Demo 零运维；并发与向量检索生产再升 |
| Q5 | Redis | **Demo 不引入**，额度用 DB 事务原子扣减；生产引入 Redis 做限流/原子 | 先跑通，再补高并发 |
| Q6 | 模型来源 | **混合**（本地 Ollama 为主日常，云端 API 跑重任务） | 兼顾费用与能力 |
| Q7 | 文档/PPT 入口 | **保留独立顶级入口**（如 v2） | 团队有协作产出需求 |
| Q8 | 语音 / 图像 | **Demo 不做**，标记 M5 可选 | 先聚焦文本智能体闭环 |
| Q9 | 隐私 | 默认全本地；云端 Key **加密存储**，不落明文 | 本地优先 |
