# AI Agent 平台 · 功能联合使用指南 & 完整性测试手册

> 用途：① 搞清每个功能「是干什么的」；② 学会把它们**串起来联合使用**；③ 按清单逐项验证功能完整性。
> 版本：当前源码（Next.js 14 + PostgreSQL + 可选 Redis）。含治理层 + 能力层全量功能。
> 前提：**对话 / 文档 / PPT / 技能 / 定时任务** 会调用大模型，务必先在「管理后台 → 模型配置」配一个可用模型并设为默认（见 §2）。

## 0. 一张图看懂「功能如何联动」

```
                         ┌──────────────────────────────────────────────┐
                         │                 治理层（团队运营）              │
                         │  注册/登录 · RBAC(admin/member/guest)          │
                         │  用户管理 · 模型配置 · 额度/超限策略 · 日志 · 评估 │
                         └───────────────┬──────────────────────────────┘
                                         │ 决定：谁能用、用哪个模型、花多少额度
                                         ▼
   知识库(RAG) ──检索──┐
       ▲               │
       │ 上传/加入知识库 │
   文件管理 ──引用/附件─┤
       ▲               ▼
       │        ┌──────────────┐   工具调用    ┌─────────────┐
       └────────│   对话(核心)  │◀────────────▶│ 连接器/工具  │
                │  FunctionCall │              │ HTTP/DB/沙箱 │
                └──────┬───────┘              │ 文件/浏览器/MCP│
                       │ 注入                  └─────────────┘
       长期记忆 ◀──────┤
       (自动沉淀/摘要) │
                       ▼
                ┌──────────────┐   被调用    ┌─────────────┐
                │   技能编排    │◀───────────│  定时任务    │
                │ 多Agent工作流 │            │ Cron/技能    │
                └──────┬───────┘            └──────┬──────┘
                       │ 产出                       │ 通知
                       ▼                           ▼
       文档(.docx) / PPT(.pptx) ──归档/绑定──▶ 项目(会话+文件+成员)
                       │
                       ▼
                会话分享/交付（只读链接 / 指定用户）
```

**一句话**：模型配置是所有 AI 功能的电源；知识库/文件/记忆是对话的「资料与记忆」；连接器/技能是对话的「手脚」；定时任务让技能自动跑；对话产出文档/PPT；项目把一切聚合；分享把成果交付出去。

## 1. 一条主线：把「一次完整的团队智能工作流」跑一遍

按顺序做，能一次覆盖 **90% 功能**，并观察它们如何互相喂数据：

1. **开店**：`/register` 注册 → 首个用户自动成为**管理员**（§3.1）。
2. **通电**：`管理后台 → 模型配置` 添加一个可用模型（如 OpenAI/DeepSeek）并**设为默认**；再添加一个带 `embedding` 能力的模型（§3.12）。
3. **建库**：`知识库` 新建一个「团队知识库」→ 上传一份 PDF/Word/Excel → 等状态变 `indexed` → 用「检索测试」验证能命中（§3.4）。
4. **存料**：`文件` 上传几个文件（可归属项目）→ 对某个文件点「加入知识库」（§3.5）。
5. **起项目**：`项目` 新建一个项目、加一个成员 → 详情里「发起会话」（§3.7）。
6. **对话**：进入带项目上下文的会话：
   - 用 `@ 引用` 拉入一个文件；用 📎 上传一个附件；用 `/ 技能` 先建一个技能再调用（§3.2）。
   - 问一个需要知识库的问题 → 看回答带**参考来源 chip**；展开**工具调用轨迹**（模型有 tools 能力时）。
   - 助手消息上点「转文档 / 转 PPT / 存为技能 / 语音播报」。
   - 打开右侧**工作空间文件栏**，确认本会话上传的文件在里面。
7. **出料**：去 `文档` / `PPT` 页，勾选「引用知识库素材」，选模板生成 `.docx/.pptx`；或在对话里直接「转文档/转PPT」（§3.3）。
8. **自动化**：`技能编排` 新建一个多节点技能（含条件/循环/工具/人工确认）→ 运行出轨迹 → 「导出」技能包；再「导入」回来。到 `定时任务` 建一个「运行技能」的定时任务 → 「立即运行」看结果与历史（§3.8/§3.10）。
9. **记忆**：`记忆` 手动加一条团队记忆；再对对话几轮 → 观察系统自动沉淀记忆；对话变长后早期内容会被**摘要压缩**（§3.9）。
10. **交付**：会话顶部「分享」→ 生成链接 → 无痕窗口打开只读页（§3.13）。
11. **治理**：回 `管理后台`：看用量趋势 + **缓存命中率** + 导出 CSV；开 `注册/邀请` 生成邀请码；在 `评估` 页跑 RAG 自检与 LLM 打分（§3.12）。
12. **收尾**：`设置` 换主题/主色（头像、气泡、激活态随色变化）；`通知` 铃铛看定时任务与额度告警（§3.11/§3.15）。

## 2. 环境与前置

- 依赖：Node ≥ 18、PostgreSQL（必选）、Redis（可选）、pnpm。
- 启动：`pnpm dev`（开发，Turbopack）或 `pnpm build && pnpm start`（生产预览）。
- 首次启动自动：建表（含幂等 `ALTER` 兼容旧库）+ 预置模型（对话：Ollama / OpenAI / DeepSeek / 通义千问 / 智谱 GLM / MiniMax / 腾讯混元 / Kimi / 商汤日日新；向量：智谱 embedding-3 / 通义 text-embedding-v4 / 硅基流动 bge-m3 / nomic-embed-text / text-embedding-3-small；已存在同 ID 的不会被覆盖）；调接口时自动迁移并补齐新增预设。
- `.env.local`：`DATABASE_URL`、`APP_SECRET`（生产必改）、可选 `REDIS_URL`/`OPENAI_API_KEY`/`LANGFUSE_*`。

## 3. 功能逐项说明（是什么 · 在哪 · 联合点）

> 标记「需模型」的须先配好默认模型。

### 3.1 账号与鉴权
- **是什么**：多账号 + JWT(httpOnly Cookie) + RBAC（admin/member/guest）。
- **入口**：`/register`、`/login`、左下角头像卡片。
- **联合点**：首个注册者是管理员 → 才能进「管理后台」配模型/管人；注册方式由后台控制（开放/邀请码/仅管理员）；Guest 为只读（写操作被拦截）。
- **验证**：首个用户带「管理员」标识；退出/重登正常；开启「邀请码」后注册页出现邀请码输入框。

### 3.2 对话（核心控制台）— 需模型
- **是什么**：流式对话 + Function Calling + 多模态，是调用其它能力的入口。
- **入口**：`/chat`。
- **能力**：
  - 流式输出、停止生成、模型切换、欢迎建议 chips、会话管理（新建/重命名/置顶/删除/搜索）。
  - **附件** 📎（文本入上下文、图片按视觉能力多模态）、**@ 引用**文件、**/ 技能**调用技能、**语音输入** 🎤。
  - **工具调用轨迹**（可展开，见工具名/参数/结果；语义缓存命中也会标注）。
  - **引用来源** chip（RAG 归因）、点赞/点踩。
  - 助手消息操作：复制 / 重新生成 / **转文档 / 转 PPT / 存为技能 / 语音播报**。
  - 右侧**工作空间文件栏**（可收起）：本会话文件，支持上传/下载。
  - 顶部**分享**按钮。
- **联合点**：对话自动带「知识库检索 + 长期记忆 + 项目上下文」；`search_knowledge`/`read_file`/`run_skill` 通过 Function Calling 触发；额度超限按策略拦截/降级/告警。
- **验证**：流式、来源 chip、轨迹展开、附件/引用/技能、转文档、分享、右侧栏。

### 3.3 文档 / PPT 生成 — 需模型
- **是什么**：把要点扩写为 `.docx` / `.pptx`。
- **入口**：`/docs`、`/ppt`，或对话里「转文档/转PPT」。
- **联合点**：可勾选「**引用知识库素材自动成文**」（内部走 RAG 检索拼进 prompt）；PPT 有 5 套模板/配色。
- **验证**：下载文件能打开；换模板颜色变化；勾选引用后内容含知识库信息。

### 3.4 知识库（RAG）— 建议配 embedding 模型
- **是什么**：多知识库（个人/团队）+ 解析切片 + 向量/词法混合召回 + 重排。
- **入口**：`/knowledge`。
- **操作**：新建知识库（名称/可见范围/embedding）→ 选库上传（txt/md/csv/pdf/docx/xlsx…）→ 检索测试（TopK 可调）→ 重新索引（回填向量）→ 删除文档/知识库。
- **联合点**：对话自动检索所有库；文件页「加入知识库」把已存文件索引进来。
- **验证**：切片数>0、状态 `indexing→indexed`、检索命中，回答出现「来源」。

### 3.5 文件管理
- **是什么**：个人/项目文件存储（本地 `data/files`）+ 存储配额。
- **入口**：`/files`。
- **操作**：上传（可选归属项目）、下载、**预览**（文本/图片/办公文档内联）、**重命名**、**移动/归属项目**、**加入知识库**、删除。
- **联合点**：对话附件、@引用、工作空间文件栏都基于这里；「加入知识库」打通 RAG。
- **验证**：用量进度变化；预览能显示；重命名/移动生效。

### 3.6 记忆系统
- **是什么**：长期记忆（个人/团队，事实/情景）+ 自动沉淀 + 早期对话摘要压缩。
- **入口**：`/memory`。
- **操作**：添加 / 编辑 / 筛选 / 删除；对话自动抽取事实偏好；长会话自动摘要。
- **联合点**：对话时检索并注入；摘要缓解超长上下文。
- **验证**：对话数轮后记忆列表出现自动条目；编辑能保存。

### 3.7 项目
- **是什么**：会话 + 文件 + 成员 的聚合容器（可见性：个人/指定成员/团队）。
- **入口**：`/projects`。
- **操作**：新建、详情、**成员增删**、「发起会话」（自动绑定项目上下文）、删除。
- **联合点**：对话自动携带项目描述与关联文件名；会话可绑定/解绑项目。
- **验证**：项目详情发起会话后，对话顶部出现项目 Tag。

### 3.8 技能编排（多 Agent）— 需模型
- **是什么**：声明式多 Agent 工作流（Supervisor/Planner/Worker/Critic）。
- **入口**：`/skills`。
- **节点类型**：`llm` / `tool`(内置检索·读文件·代码沙箱·连接器) / `condition`(包含判断) / `loop`(重复) / `human`(人工确认，可暂停续跑)。
- **操作**：新建、运行（出**执行轨迹**与最终结果，含暂停→「确认并继续」）、**历史与回放**、**导入/导出 ZIP 技能包**（含 `SKILL.md`+`skill.json`）。
- **联合点**：可被对话 `/` 调用、被定时任务调用。
- **验证**：运行有轨迹；导入导出一个技能；human 节点出现「确认并继续」。

### 3.9 连接器（工具生态）— 管理员配置
- **是什么**：可被技能/对话调用的外部工具。
- **入口**：`/connectors`。
- **类型**：`http` 请求 / `db` 只读 SQL / `builtin:file` / `builtin:sandbox`(JS 沙箱) / `browser`(Playwright，需本机安装) / `mcp`(MCP 端点，对话中自动获得对端工具)。
- **联合点**：作为 `tool` 节点被技能调用；对话中作为工具被模型自动选用（`mcp` 类型的工具在对话链路可用，技能 `tool` 节点暂不支持）；连通性「测试」。
- **验证**：配个 http 连接器点「测试」看到返回；配 `mcp` 后到对话里问一句，看模型是否报出对端工具名。

### 3.10 定时任务 — 需模型
- **是什么**：Cron / `interval:N` 周期执行 prompt 或技能。
- **入口**：`/schedules`。
- **操作**：新建（类型 prompt/技能、周期、通知 none/webhook、归属）、启停、立即运行、**执行历史**、重试。
- **联合点**：完成后写**站内通知**（铃铛）+ Webhook；运行技能走多 Agent 引擎。
- **验证**：立即运行出结果、历史有记录、铃铛收到通知。

### 3.11 设置
- **是什么**：账号 / 安全 / 外观 / 额度。
- **入口**：`/settings`。
- **操作**：改昵称、改密码、主题(深浅)、**界面风格**（小程序/经典）与**主色**（6 色，即时全局生效）、月度额度 + **超限策略** + **告警阈值**、用量进度。
- **验证**：切主色后头像/气泡/激活态随动；策略保存成功。

### 3.12 管理后台（仅管理员）— 6 个 Tab
| Tab | 内容 | 联合点 |
|---|---|---|
| 用户管理 | 添加/禁用/改角色/**重置密码**/额度策略/删除 | 决定谁能登录、什么角色 |
| 模型配置 | 增/删/设为默认/**启停**/**连通性测试**/能力标签/单价/可见角色 | 所有 AI 功能的电源 |
| 额度/用量 | 近 30 天趋势 + 估算花费 + **缓存命中率** + **导出 CSV** | 成本治理 |
| 操作日志 | 谁/何时/做了什么 | 可追溯 |
| 注册/邀请 | 注册方式（开放/邀请码/仅管理员）+ 生成/删除邀请码 | 控制新成员入口 |
| 评估 | RAG recall@k 自检 + **LLM-as-judge** 打分 | 质量调优 |

### 3.13 会话分享 / 交付
- **是什么**：把会话以**只读**方式分享。
- **入口**：对话顶部「分享」。
- **操作**：链接分享（持链可看）或指定用户（需登录且邮箱匹配）、有效期；只读页 `/share/<token>`；可在 `/api/shares` 撤销。
- **验证**：无痕窗口打开链接只读查看；撤销后失效。

### 3.14 语音 / 图像
- **语音**：对话输入区 🎤 语音输入（Web Speech）；助手消息「语音播报」。
- **图像**：附件支持图片；模型具备 `vision` 能力时作为多模态输入解析。

### 3.14.1 转文档 / 转 PPT（导出）- **入口**：对话中任意一条**助手消息**下方的操作条 → 📄「转文档」/ 📊「转 PPT」。
- **转文档（可选导出格式）**：点击 📄 按钮弹出菜单，三选一——**Word（.docx）/ Markdown（.md）/ 纯文本（.txt）**；
  「文档生成」页（`/docs`）同样提供「导出格式」下拉 + 按钮文案会跟随显示。
- **转 PPT**：按回答内容自动生成演示文稿——先由模型产出「演示主题 + 每页标题 + 3~5 条要点」的大纲，再逐页排版
  （封面 + 内容页 + 页码 + 标题色条），**不会出现空白页**；内容过长自动拆页（标题带「（续）」）。
- **归档**：生成的文件同时保存到「最近产物」，可在文档/PPT 页或工作台「最近产物」中下载。
- **注意**：导出走的是模型改写（把回答扩写成结构化成稿），不是原样复制对话内容；PPT 主题会依据回答自动贴合。
- **配色**：AI 根据内容自动从 深色科技 / 浅色商务 / 暖色活力 / 清新绿 / 极简白 中匹配一套；PPT 页与对话里的「转 PPT」都是一键生成，无需手动选择。API 调用仍可用 `theme` 参数显式覆盖。
- **技能驱动**：生成 PPT 时会**优先使用「PPT 类技能」**（名称/描述含 ppt、演示、幻灯片）的 SKILL.md 作为写作指令；
  也可在请求里显式指定 `skillId`。没有这类技能时使用内置大纲提示词。
- **对话内直接出文件**：对话里说「用 ppt-generator 帮我做一份周报 PPT」时，助手会调用 `generate_ppt` 工具，
  生成真正的 .pptx 并给出下载链接（同时归档到「最近产物」）。

### 3.15 站内通知
- **是什么**：铃铛通知（额度告警、定时任务完成/失败）。
- **入口**：左侧「通知」。
- **验证**：定时任务跑完后铃铛出现未读；点开自动标记已读。

## 5. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 跳转慢 | 开发模式首次编译（Turbopack 已缓解） | 二次访问即快；生产 `build && start` 更快 |
| 报"无可用的模型" | 未配/默认模型不可用 | 后台配可用模型并设默认 |
| 编译报 node-cron 错误 | Turbopack 不识别其动态引用 | 已在 `next.config.mjs` 外部化，勿删 |
| 知识库检索不命中 | 向量化未完成/内容无关 | 稍候或「重新索引」；确认含检索词 |
| 定时任务不自动跑 | 调度器常驻在服务进程 | 保持 `pnpm dev` 在跑；先用「立即运行」验证 |
| 429 | 1 分钟超 40 次对话 | 稍候或配 Redis |
| 换主色不生效 | 浏览器缓存 | 硬刷新 |
| `pnpm start` 报端口占用 | dev 占着 3000 | 先停 dev（`pnpm dev` 与 `pnpm start` 都用 3000） |

### 7.1 访客（guest）只读体验前后端双保险

  - Composer：只读时隐藏 📎 上传 / @ 引用 / / 技能入口（共享只读视图同理）。
  - 文档/PPT 页：生成按钮禁用，文案「访客为只读角色，无法生成」。
  - 技能页：隐藏头部编排按钮组（新建/导入/从 skills.sh 导入）、行内删除，显示只读提示；运行抽屉「运行」禁用（访客可查看与运行既有技能的入口关闭——严格只读）。
  - 定时任务页：隐藏「新建任务 / 立即运行 / 删除」。
  - 记忆页：隐藏「添加记忆 / 编辑 / 删除」。
  - 项目 / 知识库 / 文件页：隐藏「新建项目 / 新建知识库」，上传按钮禁用并提示。
  - 设置页：访客仍可自改昵称/密码，但服务端忽略其 `monthlyLimit / overQuotaAction / alertThreshold` 自改请求。
- **实现**：`SessionContext` 新增 `useGuest()`；各页面按 `isGuest` 隐藏/禁用，与服务端 403 形成双保险。

### 7.2 防重复提交
- 定时任务「立即运行」：按任务加 `runBusy` loading，运行中禁用其他任务的立即运行按钮。
- 连接器「测试」：按连接器加 `testing` loading，测试中禁用其他测试按钮。
- 文档/PPT 生成与技能「运行」本身已带 loading（此前已具备）。

### 7.3 定时任务注入时间上下文
- `runSchedule` 对 prompt 型任务自动注入 `【运行环境信息】当前时间：…（zh-CN）`，日报/周报/统计类任务不再因「不知道今天几号」而产出过期内容。技能型任务的输入 string 同样以该上下文开头。

### 7.4 文案中文化
- 项目列表「可见性」：team→团队、members→指定成员、personal→个人（此前直接显示英文枚举）。
- 连接器「可见角色」：admin→管理员、member→成员（逗号分隔中文化）。
- 记忆列表类型标签：fact→事实、episodic→情景。

### 7.5 脚本与环境
- `pnpm dev:webpack` 不再硬编码端口：改为 `next dev`（默认仍 3000；可用 `PORT=3001` 环境变量换端口）。
- `.env.local` 的 `APP_SECRET` 已换成 64 位十六进制强随机密钥。**注意**：更换密钥会使所有已登录用户的 JWT cookie 立即失效（现象：接口 401、跳回登录页），重新登录即可；生产部署务必另设生产密钥。
- **重要**：`APP_SECRET` 同时用于 AES-256-GCM 加密 `models.api_key`（`lib/crypto.ts`）。轮换密钥后须执行一次性迁移 `node scripts/reencrypt-model-keys.mjs`（用 `OLD_APP_SECRET` 指定旧密钥），否则所有模型调用报「Unsupported state or unable to authenticate data」。脚本幂等，可重复执行。

### 7.7 向量（Embedding）能力补齐与修复- **预置向量模型**（OpenAI 兼容 `/embeddings`，在「模型配置」填 Key 即用，仅管理员可见）：
  | 模型 | 接口 | 维度 | 说明 |
  |---|---|---|---|
  | 智谱 `embedding-3` | open.bigmodel.cn/api/paas/v4 | 256~2048 可选 | 语义强，支持自定义维度 |
  | 通义 `text-embedding-v4` | dashscope.aliyuncs.com/compatible-mode/v1 | 64~2048 可选 | 便宜（¥0.0005/千 token），有免费额度 |
  | 硅基流动 `BAAI/bge-m3` | api.siliconflow.cn/v1 | 1024 | 中文检索好，目前常为免费 |
  | Ollama `nomic-embed-text` | 本机 Ollama | 768 | 完全离线 |
  | OpenAI `text-embedding-3-small` | api.openai.com/v1 | 1536 | 海外账号 |
  - MiniMax 自家的 `embo-01` **未预置**：其 embedding 接口不是 OpenAI 标准格式（需 `texts`+`type`+GroupId，响应为 `vectors`），当前 SDK 无法直接调用。
- **向量模型选择规则**（`lib/ai/embed.ts`）：只在「已配置 Key 且启用」的向量模型中挑选（多个则优先默认模型）——新增预置不会抢占已配好的模型；一个都没配则自动使用**本地 384 维词频哈希向量**兜底（零成本、离线可用）。
- **修复：Redis 不可用时向量化任务被静默吞掉**。此前 `REDIS_URL` 已配置但 Redis 服务未启动时，BullMQ 入队异步失败且无兜底，导致文档状态永远停在「向量化中」、切片从未写入向量，检索只能靠词法（分数明显偏低）。现改为：入队前先探测 Redis，不可用则**同步兜底完成向量化**，保证 `indexing → indexed` 正常流转。
- **批量向量化**：文档切片按 8 条/批一次请求（`embedMany`），云端 embedding 的请求数与耗时大幅下降（实测 2 个切片仅 1 次请求）。
- **维度说明**：本机 PostgreSQL 未安装 pgvector 扩展，向量统一以 JSON 存储、检索走内存余弦 + 词法混合重排（知识库规模小无影响；若装上 pgvector，384 维的向量还会额外写入向量列以走数据库近邻搜索）。
- **换向量模型后**：旧切片的向量不会自动重算（`重建索引` 只回填缺向量的片段），需要语义一致性时请**删除旧文档重新上传**。

### 7.8 技能安装（SkillHub / skills.sh / GitHub）
- **两种入口**：
  1. **对话内**：直接说「安装技能 `@user_3b34947d/ppt-generator-skill`」→ 模型调用只读工具 `propose_skill_install` → 对话页输入框上方出现**安装提议卡片**（名称/版本/作者/来源/安全扫描/文件数/附带脚本数/说明）→ 点【确认安装】才真正入库（管理员）；成员只能发起提议并显示「待管理员确认」。
  2. **技能页**：右上「从技能源导入」→ 填 `@handle/slug`、`https://skillhub.cn/@handle/slug`、`https://skills.sh/owner/repo/skill`、`owner/repo/skill` → 立即导入为个人技能。
- **支持来源**：SkillHub（`api.skillhub.cn`，含 keen/sanbu 安全扫描结论）与 GitHub 公开仓库（skills.sh 同源）。
- **安全边界**（重要）：
  - **不执行任何第三方脚本**：SkillHub 官方协议是 `curl … install.sh | bash` 装 CLI，本平台**不这么做**；技能包里的 `scripts/*.py|*.js` 一律忽略，仅在描述中标注「附 N 个脚本，本平台不执行」。
  - 只导入 `SKILL.md` 正文，作为单步 LLM 技能的提示词；抓取内容视为**不可信数据**，不作为指令执行。
  - 请求域名固定白名单（`api.skillhub.cn` / `api.skillhub.tencent.com` / `raw.githubusercontent.com` / `api.github.com`），用户输入无法改变请求目标（防 SSRF）。
  - 提议与安装均写操作日志（`skill_propose` / `skill_install_confirm` / `skill_proposal_dismiss`）。
- **管理**：`GET /api/skills/proposals` 待确认列表；`POST /api/skills/proposals/{id}` `{action:'confirm'|'dismiss'}` 确认/忽略。
