# 文档索引

> 本目录按「用途」分层，**一层只放一类文档**，新增文档前先确认属于哪一层。
> 全部相对链接由 `node scripts/check-doc-links.mjs` 校验，避免重组后路径漂移。

## 目录结构

| 目录 | 放什么 | 不放什么 |
|---|---|---|
| `01-需求/` | 需求基线、需求实现对照、外部给的改造清单 | 实现细节、迭代流水账 |
| `02-设计/` | 架构与技术说明、Agent 能力矩阵（清单→代码对照） | 页面规范、截图 |
| `03-迭代/` | 每一轮迭代的计划与记录、优化评估、改版记录 | 需求原文 |
| `04-规范/` | 界面开发规范（写界面时的唯一依据）、Git 分支与发布规范 | 实现说明 |
| `05-手册/` | 面向最终用户的手册 + 真机截图 | 开发者文档 |
| `06-参考/` | 三方系统接入说明、外部采集点存档、UI 走查截图 | 本项目原创设计 |

## 维护约定

1. **新增迭代记录**按 `迭代计划-vX-主题.md` / `优化记录-vX-主题.md` 命名，放 `03-迭代/`，并在本页清单补一行。
2. **文档里引用其他文档**一律用相对路径；改完跑 `node scripts/check-doc-links.mjs`。
3. **被取代的文档**不删除，移到 `99-归档/` 并在文首加一行「已被 xxx 取代」。
4. **截图**如需入库，跟随所属文档放在同一目录下，保证相对引用不失效。**入镜即公开**：截前必须清掉真实文件名、账号名、业务数据与会话记录，否则宁可不放图。
